Suponiendo que el usuario controla la entrada estándar, el siguiente código tiene problemas de
seguridad

```c
#define MAX_BUF 4096
void saludo(void) {
    char nombre[MAX_BUF];
    printf("Ingrese su nombre: ");
    fgets(nombre, MAX_BUF, stdin);
    printf(nombre);
}
```

a) ¿Dónde se introduce el problema de seguridad?

Se introduce en `printf(nombre);`, nombre se interpreta como una cadena de formato.
Podes poner %p, %x o %n que intepreta como operaciones, algunas son leer un dato, que si no lo pasas estas leyendo memoria, y el %n incluso quizas escribirla, aunque aparentemente no siempre anda.

b) ¿Qué datos del programa (registros, variables, direcciones de memoria) pueden ser controladas por el usuario? (Ayuda: lea con mucho detalle man printf y permita sorprenderse)

El array nombre. Donde puede escribir 4096 chars

- %x y %p: lectura de valores de registros o del stack.
- %s: lectura de memoria desde una dirección interpretada como puntero.
- %n: escritura en una dirección de memoria interpretada como puntero.

c) ¿Es posible sobreescribir la dirección de retorno a la que vuelve alguna de las llamadas a la función printf?
Es posible que se pueda escribir en el stack con %n. Pisando con el valor "cantidad de chars escritos hasta ahora". Dudo que puedas poner mucho, porque tenes un limite de 4096, pero romper el programa quizas.
Ademas podrias pasarle el parametro de donde escribir al %n asi que aparentemente podes pisar el propio retorno de printf.Pero tenes que tener algo desde antes en el stack creo.

BUGS
Code such as printf(foo); often indicates a bug, since foo may
contain a % character. If foo comes from untrusted user input, it
may contain %n, causing the printf() call to write to memory and
creating a security hole.
