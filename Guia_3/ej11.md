Ejercicio 11 (Read y Write)

Se quiere simular la comunicación mediante pipes entre dos procesos mediante las syscalls read() y write(), pero usando memoria compartida (sin usar file descriptors). 
Se puede pensar al pipe como un buffer de tamaño N, donde en cada posición se le puede escribir un cierto mensaje. 
El read() debe ser bloqueante en caso que no haya ningún mensaje, y si el buffer está lleno, el write() también debe ser bloqueante. 
No puede haber condiciones de carrera y se puede suponer que el buffer tiene los siguientes métodos: pop() (saca el mensaje y lo desencola), push() (agrega un mensaje al buffer).

Nota:
mutex_pipe.signal();
mensajes.signal();

Esto seria ligeramente mas efectivo, porque evitariamos levantar al lector, y dormirlo devuelta si no soltamos el mutex_pipe, asi seria mas efectivo

```c
write(*buffer, mensaje* msg){
    buffer.push(msg);
}
read(*buffer, mensaje* msg){
    msg = buffer.pop();
}

//Shared
mensaje *buffer[n];
mutex_escritura(1);
mutex_lectura(1);
sem mutex_pipe(1);
sem mensajes(0); // Los mensajes que ya hay
sem espacio(n); // El espacio en el buffer

// --- A ---
mensaje = "Hola";
while(1){
    mutex_escritura.wait();
    espacio.wait();
    // Una ves que tiene permiso de escribir, y el buffer no esta lleno, nos garantiza que vamos a tener una escritura exitosa (o deberia)
    // Podemos pedir el pipe, si lo hicieramos antes y no tuvieramos alguno de los otros recursos garantizados, habria deadlock
    mutex_pipe.wait();

    write(buffer, &mensaje)
    mensajes.signal();
    mutex_pipe.signal();
    mutex_escritura.signal();
}


// --- B ---
mensaje;
while(1){
    mutex_lectura.wait();
    mensajes.wait();
    mutex_pipe.wait();
    read(buffer, &mensaje)
    mutex_pipe.signal();
    espacio.signal(); //Acabamos de leer, asi que el buffer esta 1 mas libre
    mutex_lectura.signal();
}
```
